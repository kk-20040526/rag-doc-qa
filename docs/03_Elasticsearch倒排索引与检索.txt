Elasticsearch 是一个基于 Lucene 的分布式搜索引擎，核心数据结构是倒排索引。正排索引是"文档 → 它包含哪些词"，倒排索引反过来记录"词 → 哪些文档包含它、出现几次、在什么位置"。查询时不需要扫全量文档，直接按词查倒排表就能定位候选文档，所以检索延迟很低。

ES 的默认 HTTP 端口是 9200，集群通信端口是 9300。用 Docker 或压缩包部署后，访问 http://localhost:9200 能看到集群名、版本和节点信息，这是判断服务是否起来的第一个检查点。ES 8.x 的 Windows 压缩包自带 JDK，不需要系统预装 Java。

mapping 决定字段怎么被索引。类型 text 的字段会被分词、进入倒排索引、可以全文检索；类型 keyword 的字段不做分词，整串作为一个词，适合精确匹配、聚合、排序。本项目把文档内容映射为 text、来源文件名映射为 keyword，这样既能按内容检索，又能按来源分组统计。

检索时常用的查询类型是 match。match 会把查询文本先分词，再对目标字段做布尔匹配，最后按相关性打分。如果需要跨多个字段一起检索，用 multi_match，可以指定 best_fields（取最高分字段）或 most_fields（多字段得分累加）。需要注意的是，单字段 match 和多字段 multi_match 是两种不同的查询构造，写文档时要和代码保持一致。

批量写入用 bulk API，把成百上千条文档打包成一次请求，比逐条 index 快一个数量级。写入后不会立刻可查，因为 ES 有刷新间隔（默认 1 秒），需要立即可查时调用 refresh，或者在 bulk 请求里指定 refresh。这一点在"建完索引马上演示检索"的场景里特别容易踩坑：不 refresh 就会出现索引建好了但搜不到的空窗。

ES 相对内存检索的优势是可持久化、可水平扩展（加节点分片）、支持高亮、支持聚合统计。代价是要额外部署一个服务、要维护索引、查询有网络开销，本项目实测 ES 检索约 8 毫秒（含网络往返），BM25 内存检索约 2 毫秒。
