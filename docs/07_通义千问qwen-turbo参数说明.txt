通义千问（Qwen）是阿里云的大模型系列，通过阿里云百炼平台对外提供服务。系列里有不同规格：qwen-turbo 主打低延迟与低成本，qwen-plus 均衡，qwen-max 效果最好但最贵。做 RAG 这类"答案已经被检索片段约束住"的任务，qwen-turbo 通常是性价比最高的选择，因为难度主要在检索，不在生成。

调用方式有两种。一种是 DashScope 原生 SDK，用 dashscope 包；另一种是 OpenAI 兼容接口，把 base_url 指到 dashscope 的 compatible-mode 地址、把 api_key 设成百炼的 Key，就能用 openai 的客户端直接调。本项目用的是后者，配置项在 .env 里：DASHSCOPE_API_KEY、QWEN_MODEL、QWEN_BASE_URL。

关键参数里，temperature 控制输出的随机性，取值 0 到 1 附近，事实型问答建议 0 到 0.3，越低越稳定。top_p 是核采样阈值，和 temperature 二选一调即可，同时大幅调整容易失控。max_tokens 限制输出长度，留太小会把答案截断。stream 控制是否流式返回，流式适合前端边生成边显示，但要注意客户端要能处理分片。

计费按输入输出 token 数结算，所以上下文塞得越多越贵。这也是"Top-K 不要贪多"的经济学理由：多塞 5 段无关片段，可能既没提升答案质量，又让每次调用的成本翻倍。

实践中的坑有两个。一是 Key 没配或失效时，报错信息往往很含糊，建议先单独跑一次最小调用验证连通性，再排查业务代码。二是限流：免费额度或低配额度下并发稍高就会触发限流，RAG 页面里连点搜索按钮很容易撞上，前端应做按钮禁用或加节流。
